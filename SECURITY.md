# Security and Data Handling

This demo contains synthetic ontology examples only.

- Do not commit credentials, API keys, access tokens, production graph endpoints, customer data, claim data, policyholder data, or other confidential information.
- Use repository/CI secret stores for credentials in a production implementation.
- Approved ontology artifacts should be published through controlled service identities and least-privilege deployment roles.
- Treat ontology releases as governed enterprise artifacts because semantic changes can affect data classification, APIs, knowledge graphs, analytics, and AI/RAG behavior.
